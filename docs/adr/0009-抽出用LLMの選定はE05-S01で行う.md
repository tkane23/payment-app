# 0009 抽出用LLMの選定はE05-S01で行う

- ステータス：決定（選定の時期と条件）
- 日付：2026-09-27
- 関連ストーリー：E00-S02（選定は E05-S01、マスキングは E12-S03）

## 背景

領収書メールやスクショから、プラン名・更新日などを抽出するためにLLMを使う。使い始めるのは S9 で、それまでに精度と料金を実際の形式で比べられる。

## 選択肢

| 案 | 長所 | 短所 |
| --- | --- | --- |
| AWS Bedrock 経由 | AWS の契約・請求・権限管理の中で使える（0002） | 使えるモデルや機能が提供元のAPIより遅れることがある。料金は Bedrock の価格表による |
| 提供元のAPIを直接使う（Anthropic 等） | 最新モデルと機能をすぐ使える | 契約先が増える |
| 今は決めず、E05-S01 で比べて決める | 実際の領収書（テスト用）で精度と料金を比べられる | 決定が後になる |

参考（Anthropic の公式価格、1件あたり入力約3,000・出力約500トークン、1ドル＝150円の概算）：Claude Opus 5 約4円、Claude Sonnet 5 約2円、Claude Haiku 4.5 約1円。

## 決定

提供元とモデルは E05-S01 で、精度と料金を比べて決める。プロダクトオーナーの判断（2026-09-27）。

どの提供元にする場合も、次の条件は今の時点で確定とする。

- 送信前に個人情報をマスキングする（`docs/security.md`、E12-S03）。
- 学習に利用されない契約のAPIだけを使う。
- 送信内容をログに残さない。
- 領収書の原文・画像は、抽出後に削除する。

## 影響

- E05-S01 の完了時に、選んだ提供元・モデル・理由を新しいADRに記録し、`docs/architecture.md` の「OCR・抽出」を更新する。
- 抽出の処理はインターフェースで抽象化し、提供元を変えても `packages/core` に影響しないようにする。
