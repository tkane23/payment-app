# 0001 モノレポとCIのツール選定

- ステータス：決定
- 日付：2026-09-27
- 関連ストーリー：E00-S01

## 背景

アプリ（Expo）とサーバーと診断ロジックを1つのリポジトリで扱い、プルリクエストごとに型チェック・Lint・単体テストを自動で回す必要がある。pnpm + Turborepo、TypeScript strict、GitHub Actions は `CLAUDE.md` とストーリーで指定済み。残る選択は、Lint とテストのツール、ワークスペース間の参照方法、Node のバージョン。

## 選択肢

| 領域 | 選択肢 |
| --- | --- |
| Lint | ESLint（flat config）+ typescript-eslint ／ Biome |
| テスト | Vitest ／ Jest |
| ワークスペース間の参照 | TypeScript のソースを直接参照 ／ 各パッケージをビルドして参照 |
| Node | 22 LTS ／ 24 LTS |

## 決定

- **Lint**：ESLint + typescript-eslint（`strict` と `stylistic`）。Expo・React Native のプラグインがそろっており、E00-S04 でそのまま拡張できるため。
- **テスト**：Vitest。TypeScript を設定なしで実行でき、`packages/core` の純粋関数のテストが速い。`apps/mobile` は E00-S04 で jest-expo に替えることがある。
- **ワークスペース間の参照**：ビルドせず、`exports` で `src/index.ts` を直接参照する。型チェックは `noEmit`。ビルド手順がない分、変更がすぐ反映される。
- **TypeScript**：6.0 系に固定（`~6.0`）。TypeScript 7（Go 実装）は typescript-eslint が未対応（peer は `<6.1.0`）のため。typescript-eslint が対応したら 7 へ上げる。
- **pnpm**：12.6.0 を `packageManager` で固定。導入は `npm install -g pnpm`。`corepack enable` は Node のインストール先（Windows では Program Files）への書き込みが必要で、管理者権限のない環境で失敗するため採らない。pnpm は `packageManager` のバージョンに自動で合わせる。
- **Node**：24 LTS（`.nvmrc`）。型注釈を取り除いて `.ts` をそのまま実行できるため、`apps/api` の開発起動にビルドがいらない。そのため `erasableSyntaxOnly` を有効にし、enum などの構文は使わない。
- **CI**：`pull_request` と `main` への push で、`pnpm install --frozen-lockfile` → `pnpm typecheck` → `pnpm lint` → `pnpm test` を実行する。ルートのスクリプトは Turborepo 経由で全ワークスペースに対して走る。
- **マージの防止**：GitHub のブランチ保護で `main` への直接 push を禁止し、CI ジョブの成功を必須にする。
- **API フレームワーク**：まだ選ばない（E00-S02 で確定）。起動確認には `node:http` の最小サーバーを置く。

## 影響

- パッケージを外部に公開するときや、Node で実行するライブラリを作るときは、ビルド手順の追加が必要になる。
- リポジトリ構成のテストはルートの `tests/` に置き、`//#test:repo` などのルートタスクとして CI で実行する。
- Expo は Metro でバンドルするので、ソースを直接参照する方式と相性がよい。Metro の設定は E00-S04 で確認する。
