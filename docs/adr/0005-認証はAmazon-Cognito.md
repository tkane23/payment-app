# 0005 認証はAmazon Cognito

- ステータス：決定
- 日付：2026-09-27
- 関連ストーリー：E00-S02（実装は E01-S01）

## 背景

会員登録・ログイン（メール・Apple・Google）が必要。パスワードを自前で保存しない方針（`docs/architecture.md`）のため、実績のある認証基盤を使う。

## 選択肢

| 案 | 長所 | 短所 |
| --- | --- | --- |
| Amazon Cognito | AWS に集約できる（0002）。東京リージョン。利用者1万人程度まで無料枠 | 画面や設定の自由度はやや低い |
| Auth0 | 機能が豊富で設定しやすい | 契約先が増える。利用者が増えると高くなりやすい |
| Supabase Auth | DB と一体で使いやすい | 基盤を AWS に集約する判断（0002）と合わない |

## 決定

Amazon Cognito（東京）を採用する。メールアドレス、Sign in with Apple、Google でのログインに対応する。

## 影響

- 会員の認証情報は Cognito（東京）に保存され、アプリのDBにはパスワードを置かない。
- API は Cognito が発行するトークンを検証して利用者を特定する。
- iOS で他社ログイン（Google）を提供する場合、Apple のルールにより Sign in with Apple も必要になる（E01-S01 で対応）。
