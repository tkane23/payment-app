# 0004 個人データの保存と暗号化

- ステータス：決定
- 日付：2026-09-27
- 関連ストーリー：E00-S02（実装は E12-S01）

## 背景

明細・定期課金・アグリゲーターのトークンなど、金融に関わる個人データを保存する。`docs/security.md` は、東京での保存、保存時の暗号化、トークンのアプリ層での暗号化、KMS での鍵管理を求めている。保存先のDBと暗号化の方式を決める。

## 選択肢

| 領域 | 選択肢 |
| --- | --- |
| DB | Amazon RDS for PostgreSQL ／ Amazon Aurora PostgreSQL ／ DynamoDB |
| 保存時の暗号化の鍵 | AWS管理キー ／ カスタマー管理キー（KMS） |
| トークンの暗号化 | DB の暗号化だけ ／ アプリ層でも暗号化（KMS のエンベロープ暗号化） |

## 決定

- **DB**：Amazon RDS for PostgreSQL（東京）。明細の集計や定期課金の検出で結合・集計が多いため、リレーショナルDBにする。小さく始められ費用が読みやすい RDS を選び、Aurora は規模が必要になったら検討する。開発中は1台、公開時は2台構成（Multi-AZ）にする。
- **保存時の暗号化**：RDS のストレージ暗号化を有効にし、鍵は KMS のカスタマー管理キーにする（鍵の利用履歴を監査でき、無効化もできるため）。スナップショット・バックアップも同じ鍵で暗号化され、東京に置く。
- **トークンの暗号化**：アグリゲーターのトークンはアプリ層でも暗号化する。KMS でデータキーを発行し、AES-256-GCM で暗号化して、暗号化したデータキーと一緒に保存する（エンベロープ暗号化）。平文はメモリ上でのみ扱う。
- **通信**：TLS 1.2 以上。RDS への接続も TLS を必須にする。

## 影響

- 保存場所・暗号化の一覧は `docs/architecture.md` の「個人データの保存場所と暗号化」に記載する。
- KMS の鍵は用途ごとに分ける（DB 用、トークン用）。KMS の費用は鍵1つあたり月1ドル程度＋利用回数。
- PostgreSQL の行単位アクセス制御（RLS）の採否は E12-S01 で決める。それまでは、すべてのクエリで利用者IDによる絞り込みを必須とする。
- バックアップからの削除期限は `docs/security.md` で「要決定」のまま。退会処理（E01-S03）までに決める。
