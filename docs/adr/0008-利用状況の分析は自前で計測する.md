# 0008 利用状況の分析は自前で計測する

- ステータス：決定
- 日付：2026-09-27
- 関連ストーリー：E00-S02（実装は E13-S01）

## 背景

提案の実行率などのKPIを計測する必要がある。候補だった PostHog のクラウド版は、データの保存先が米国か欧州で、日本を選べない。

## 選択肢

| 案 | 長所 | 短所 |
| --- | --- | --- |
| PostHog（個人データを送らない） | 分析画面がすぐ使える | データが国外に保存される。送る内容を常に管理する必要がある |
| 自前で計測 | データが東京のDBに残り、国外に出ない。追加費用がほぼない | 集計や分析画面を自分たちで作る必要がある |

## 決定

外部の分析サービスは使わず、自前で計測する。プロダクトオーナーの判断（2026-09-27）。

- 操作イベント（画面を開いた、提案に反応した、実行した等）を、自分たちの RDS（東京）に記録する。
- イベントに明細の内容・金額の一覧・氏名などは含めない。

## 影響

- KPIの定義・イベントの一覧・集計方法は E13-S01 で決める。
- 分析画面は、まずSQLの集計で始め、必要になったら管理画面（E11-S01）に追加する。
