# 0003 APIフレームワークはHono

- ステータス：決定
- 日付：2026-09-27
- 関連ストーリー：E00-S02

## 背景

`apps/api` のフレームワークを決める。開発はAIが中心で、チームは小さい。TypeScript strict で統一している（0001）。

## 選択肢

| 案 | 長所 | 短所 |
| --- | --- | --- |
| Hono | 軽量でコードが少ない。型付きのルーティングと検証。Lambda・コンテナのどちらでも動く | 構造（層の分け方）は自分たちで決める必要がある |
| NestJS | 大規模向けの決まった構造、DI、豊富な機能 | コード量と学習量が多い。デコレーター中心で、`erasableSyntaxOnly` 等の設定と相性が悪い |

どちらもオープンソースで、利用料はかからない。

## 決定

Hono を採用する。プロダクトオーナーの判断（2026-09-27）。

## 影響

- E00-S01 で置いた `node:http` の最小サーバー（`/health`）は、APIの最初の機能ストーリーで Hono に置き換える。
- 層の分け方（ルーティング → ユースケース → `packages/core` の純粋関数 → DBアクセス）は、最初の機能ストーリーで決めてADRに残す。
- 実行環境（0002）が Lambda・コンテナのどちらになっても、Hono のまま動かせる。
