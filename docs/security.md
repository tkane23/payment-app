# セキュリティ方針

金融データを扱うため、セキュリティは機能より優先します。判断に迷ったら安全側を選び、プロダクトオーナーに確認してください。

## 保存しないもの

- 銀行・カードのログイン情報（ID・パスワード）
- 領収書メールの原文、スクショの画像（抽出後に削除）
- カード番号・口座番号の全桁

## 暗号化

- 通信はTLS 1.2以上。
- DBは保存時に暗号化する。
- アグリゲーターのトークンは、アプリ層でも暗号化し、鍵はクラウドの鍵管理サービスで管理する。

## LLM利用時のマスキング

外部のLLMに送る前に、以下を除去またはマスクする（ストーリー E12-S03）。

| 対象 | 例 | 処理 |
| --- | --- | --- |
| 氏名 | 山田 太郎 | `[NAME]` に置換 |
| メールアドレス | taro@example.com | `[EMAIL]` |
| 電話番号 | 090-1234-5678 | `[PHONE]` |
| 住所 | 東京都… | `[ADDRESS]` |
| カード番号・口座番号 | 4桁以上の連続数字の組 | `[NUMBER]`（下4桁の保持は要検討） |

- 学習に利用されない契約のAPIだけを使う。
- 送信内容をログに残さない。

## アクセス制御と監査

- 管理画面の権限は最小限に分ける（辞書編集のみ、問い合わせ対応など）。
- 個人データの閲覧・変更はすべて監査ログに残す。ログにはトークンや明細の全文を含めない。

## データ削除

- 退会・連携解除で関連データを削除する。削除の完了を監査ログに残す。
- バックアップからの削除期限を定める（要決定）。

## 公開前

- 外部の脆弱性診断を受け、重大度「高」以上をすべて修正する（ストーリー E12-S04）。
- 利用規約・プライバシーポリシーは専門家の確認を経る。
