# 開発プロセス（AI開発 × アジャイル）

## 役割

| 担い手 | 役割 |
| --- | --- |
| プロダクトオーナー（人） | 優先順位の決定、受け入れ判断、契約・アカウント・法務、実機での確認 |
| AI開発者 | 設計、実装、テスト、ドキュメントとADRの更新 |
| 外部の専門家（スポット） | セキュリティ診断、コードレビュー、規約類の確認 |

## スプリント

- 1スプリント＝1週間。
- 月曜：プロダクトオーナーがそのスプリントのストーリーを確定（`backlog/sprints.md`）。
- 期間中：AIがストーリーを1本ずつ実装し、プルリクエストを作る。
- 金曜：実機で動作を確認し、受け入れ判断。可能なら利用者候補の5人程度に触ってもらう。
- 振り返り：うまくいかなかった点を、このファイルかCLAUDE.mdに反映する。

## 1ストーリーの流れ

1. ストーリーファイル（`backlog/stories/<ID>.md`）を読む
2. 不明点を質問する
3. 受け入れ条件ごとにテストを書く
4. 実装する
5. 型チェック・Lint・テストをすべて通す
6. プルリクエストに、受け入れ条件ごとの結果と実機での確認手順を書く
7. プロダクトオーナーが確認してマージ
8. バックログ（スプレッドシート）のステータスを「完了」にする

## 完了の定義（Definition of Done）

- 受け入れ条件をすべて満たし、それぞれにテストがある
- CI（型チェック・Lint・テスト）が通っている
- 個人情報がログに出ていない
- 実機で動作を確認できる手順がプルリクエストに書かれている
- 仕様・設計の判断をした場合、ADRが追加されている
- プロダクトオーナーが受け入れた

## バックログの管理

- 正はスプレッドシート（優先度・スプリント・ステータス）。
- ストーリーの中身（受け入れ条件）は `backlog/stories/` のMarkdownを正とする。
- ストーリーを追加・変更したら、両方を更新する。
